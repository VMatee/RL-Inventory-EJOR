# Data governance

Study design: [DATASET_PLAN.md](DATASET_PLAN.md) fixes **two external retail-sales datasets (M5 primary, original 2017 item-level Favorita external)** plus a synthetic-data track generated by the research program, not downloaded. Do not add substitutes without documenting a scientific reason.

**M5:** five public source CSVs were locally acquired, validated by filesize and Zenodo MD5 and cross-checked against published schema/rows. See [data/sources/M5.md](sources/M5.md) and [tracked source/hash registry](manifests/m5_verified_20261017.json). Raw bytes stay local under `data/raw/m5/` and ignored by Git.

**Favorita:** not downloaded. The original `favorita-grocery-sales-forecasting` Kaggle competition requires a login, accepted competition rules and credential configuration on this PC. See [data/sources/FAVORITA.md](sources/FAVORITA.md). Do not use the different product-family `store-sales-time-series-forecasting` dataset as if identical.

Check from the `github/` checkout:

```bash
../code/.venv/bin/python scripts/fetch_m5.py --verify-only
../code/.venv/bin/python scripts/fetch_favorita.py --status
```

Never commit raw M5/Favorita datasets or derived restricted artifacts. Record licenses, source URLs, acquisition dates, hashes, preprocessing, target series eligibility, and time cutoffs. Retail sales are a proxy for demand and may be censored. Do not use future test outcomes to filter series. Report product-specific, cross-series, pretrained, calibration and validation information budgets separately. Favorita original records can omit zero sales and represent returns as negative or fractional units; explicit conversion and missingness rules are required before comparison with M1's integer demand model.
